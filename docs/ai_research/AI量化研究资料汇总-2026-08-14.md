# 面向对话式因子研究与选股的 AI 量化研究备忘录

日期：2026-08-14

## 一句话结论

最有研究价值的方向不是让大模型直接“预测明天涨哪只股票”，而是把它作为量化研究员的协作层：理解投资目标，检索数据和文献，提出可解释的经济假设，编译成受限因子表达式，调用确定性的回测与统计审计工具，再根据证据决定是否继续搜索。

因此，产品最终应回答的不是“模型说买什么”，而是：

> 在给定股票池、日期、持有期、交易约束和数据可得性下，哪些候选信号通过了哪些证据检查，为什么被保留或淘汰，当前推荐的组合暴露是什么，结果有多大不确定性。

## 2. 推荐的方法论：LLM 研究员 + 确定性量化引擎

建议采用以下分层，不让 Agent 直接修改核心计算逻辑：

```text
用户目标
  -> 研究任务编译器
  -> 文献/数据/字段/因子假设 Agent
  -> 受限表达式 DSL
  -> 表达式验证与回测工具
  -> 统计审计与反事实检查
  -> 因子选择/组合/股票排序
  -> 可追溯研究报告与下一轮问题
```

### 2.1 用户输入应先变成 Research Spec

自然语言不能直接进入回测。第一步把对话编译为结构化任务：

```json
{
  "objective": "寻找中期超额收益信号",
  "universe": "用户选择的股票池",
  "as_of_date": "明确的数据截面日期",
  "horizon": "20 trading days",
  "holding_period": "20 trading days",
  "risk_constraints": ["行业中性", "单票权重上限"],
  "allowed_data": ["公开财务", "价格成交量", "已授权新闻"],
  "cost_model": {"commission": 0.0003, "slippage": 0.001},
  "success_criteria": ["样本外 Sharpe", "RankIC", "换手率", "稳定性"],
  "evidence_policy": "必须保存数据快照、来源和发布时间"
}
```

如果用户没有提供持有期、成本或股票池，Agent 应追问或使用明确的默认值，并在报告中显示，而不是默默猜测。

### 2.2 Agent 分工

1. **任务澄清 Agent**：把“找高成长股”“找低回撤因子”转成目标、约束、时间和评估指标。
2. **数据侦察 Agent**：读取字段字典、覆盖率、更新频率、缺失率、可用时间和字段权限；不允许模型凭空发明字段。
3. **研究假设 Agent**：检索论文、公司公告和既有研究记录，输出经济机制、方向、适用状态和失败条件。
4. **因子构造 Agent**：只在白名单字段与算子中生成候选表达式，并解释每个算子的角色。
5. **实验 Agent**：调用表达式校验、批量因子回测和组合回测工具，返回结构化指标。
6. **统计审计 Agent**：检查前视偏差、数据泄漏、样本选择、重复试验、交易成本、容量、行业暴露和区间稳定性。
7. **组合与推荐 Agent**：在通过门槛的候选中进行去相关、风险约束和组合构建；推荐的是“有条件的排序结果”，不是无条件买入指令。
8. **报告 Agent**：把证据、假设、结果、局限和下一步实验写成用户可以审阅的研究卡片。

每个 Agent 都应有固定输入输出 schema，不应只返回一段自由文本。

## 3. 与现有项目的对应关系

你们现在的 `single_factor` 和 `custom_backtester` 已覆盖了数值研究的核心路径：

- 单因子候选生成与质量筛选；
- Alpha 表达式规范化和受限求值；
- 因子批量回测；
- 因子互相关过滤和组合；
- 保存运行清单、指标和回测结果；
- Streamlit 工作台和后台任务。

因此建议新增一个薄的 `research_agent` 或 `ai_research` 层，主要负责：

- 对话解析和 Research Spec；
- 工具注册与权限控制；
- 提示词、模型、数据快照和实验版本记录；
- 文献及历史实验检索；
- 把 Agent 输出转换为现有 CLI/函数接受的 JSON；
- 将回测结果重新注入 Agent 的下一轮上下文。

不要让 LLM 直接拼接 Python 代码、直接读写任意文件或绕过表达式白名单。它只能生成 DSL、配置和工具调用参数。

## 4. 实验记录是 AI 系统的核心资产

每次候选实验至少保存：

```text
research_session_id
user_intent
research_spec
prompt_template_version
model_id_and_parameters
knowledge_sources_and_retrieval_time
data_snapshot_id_and_available_as_of
universe_id
expression_and_canonical_expression
operator_and_field_whitelist
backtest_config_and_cost_model
in_sample_metrics
out_of_sample_metrics
subperiod_metrics
exposure_and_turnover_metrics
audit_flags
accepted_or_rejected
rejection_reason
parent_candidate_ids
```

保留拒绝候选尤其重要。否则 Agent 会反复生成类似失败因子，或者只展示成功案例而无法估计搜索后的选择偏差。

## 5. “推荐股票”应如何定义

推荐层建议输出四部分，而不是一句“建议买入”：

1. **排序**：在指定截面、股票池和持有期下的因子分数与排名。
2. **证据**：样本外收益、RankIC、换手、最大回撤、行业暴露、历史分段稳定性和成本敏感性。
3. **条件**：只有当流动性、行业暴露、风险预算和数据新鲜度满足条件时才成立。
4. **不确定性**：候选间分歧、滚动窗口波动、不同模型/参数下的排序稳定性，以及未覆盖的信息。

股票推荐是回测和组合约束的下游呈现，不应成为 Agent 的第一步。第一步应该是明确“在什么定义下推荐”。

## 6. 最小可行版本

### V1：对话式因子研究助手

- 用户输入研究目标；
- Agent 输出 Research Spec；
- 用户确认后调用现有因子生成和回测；
- 返回 Top 候选、失败原因和一页研究卡片；
- 所有结果保存到实验注册表。

### V2：研究记忆和文献 RAG

- 对论文、内部因子笔记和历史回测建立可检索索引；
- 每个新候选先检查相似因子和历史失败案例；
- 把“经济机制”和“表达式结构”分开检索，避免只按关键词匹配。

### V3：多 Agent 研究循环

- 研究假设、数据侦察、因子构造、回测和审计并行运行；
- 由评审 Agent 统一汇总；
- 允许用户在关键节点修改约束或否决研究方向；
- 增加因子衰减监控和自动复验。

## 7. 建议的评估指标

除了模型回答质量，还要评估研究系统本身：

- 任务解析正确率：是否正确识别股票池、日期、持有期和约束；
- 字段引用准确率：是否只使用存在且在当时可得的字段；
- 表达式可执行率：生成候选中通过 DSL 校验的比例；
- 有效候选率：通过样本外、成本和审计门槛的比例；
- 重复率与相似度：是否重复历史失败候选；
- 研究效率：达到固定有效候选数所需的试验次数；
- 研究完整性：是否保存证据、拒绝原因和版本信息；
- 稳定性：换时间段、股票池、成本模型和随机种子后结论是否一致。

## 8. 最值得先做的三个实验

### 实验一：自然语言到因子研究任务

固定 20 个研究问题，比较通用模型、带字段字典的模型、带历史失败案例的模型在任务解析、字段合法性和可执行率上的差异。

### 实验二：人机交互是否减少搜索成本

对同一批投资直觉，比较“单轮 LLM 生成”“人机多轮反馈”“Agent 自动搜索”达到相同有效因子数量时的候选数、重复率和样本外质量。

### 实验三：审计 Agent 是否降低虚假优越性

让生成 Agent 产生大量候选，再分别经过普通筛选和审计 Agent，比较样本内与样本外 Sharpe 差距、成本敏感性、子区间稳定性和多重检验修正后的结果。

## 9. 结论

你们可以把已有系统定位为“数值研究执行层”，新增的 AI 部分定位为“研究协作层”。真正的创新点包括：

- 对话目标可编译为可执行研究任务；
- 文献、字段、实验和失败案例形成闭环记忆；
- Agent 通过工具而不是自由文本驱动因子与回测；
- 每个推荐都能回溯到假设、数据时间、表达式、回测和审计证据；
- 人可以在关键决策处介入，模型不会静默改变研究口径。

这条路线既能体现 AI，又保留量化研究最重要的可复现性和统计纪律。
