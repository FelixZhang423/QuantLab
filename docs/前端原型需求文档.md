# 量化因子研究平台 · Web 前端原型需求文档

> 文档目的：指导高保真可点击原型的绘制与开发。原型确认后，本方案中的页面骨架、组件规范、mock 数据结构将直接作为正式前端的开发依据。
> 原型技术栈：React 18 + Vite + TypeScript + Ant Design 5 + ECharts + axios mock 层（无后端）。

---

## 1. 项目背景与目标

### 1.1 背景

QuantLab 是股票因子生成与回测平台，现有前端为 Streamlit 单文件应用（11 页签平铺、默认外观、无认证、任务状态需手动刷新）。现决定重构为企业级 Web 应用。

### 1.2 目标

1. 用 5 个核心页面验证信息架构与交互规范（原型阶段）
2. 达到企业级应用的视觉与交互水准（统一设计语言、完整状态反馈）
3. 原型骨架可直接升级为正式前端，mock 层可无缝替换为真实 API
4. 本期不考虑高并发、多实例、SSO；预留扩展位

### 1.3 非目标（本期不做）

- 真实后端接入（原型全部用 mock 数据）
- 细粒度权限（只做两级角色：管理员 / 研究员）
- 移动端适配（目标分辨率 ≥ 1366px 桌面）
- 股票池 / 因子生成 / 因子组合 / 系统管理等页面的原型（原型确认后按同一规范平移，见第 9 节）

## 2. 用户角色

| 角色 | 描述 | 原型中可见 |
|---|---|---|
| 研究员 | 日常使用：查看数据、提交回测、监控任务、查看结果、写备注 | 主要角色，默认登录角色 |
| 管理员 | 在研究员基础上可管理用户、查看审计日志 | 仅登录页与顶栏用户菜单中体现角色标识 |

## 3. 原型范围

共 **5 个页面** + 完整导航骨架：

| 编号 | 页面 | 核心验证点 |
|---|---|---|
| P1 | 登录页 | 品牌感、表单交互 |
| P2 | 总览 Dashboard | 信息架构、数据一览 |
| P3 | 任务中心 | 实时状态、进度、日志（体验核心页） |
| P4 | 手动回测 | 复杂表单 + 结果展示 |
| P5 | 结果详情 | 指标卡、图表、下载、备注 |

**页面流转**：

```
登录(P1) → 总览(P2) ⇄ 任务中心(P3)
                │
                └→ 手动回测(P4) → 提交任务 → 任务中心(P3) → 结果详情(P5)
```

### 4.3 状态与色彩

| 任务状态 | 颜色 | 图标 |
|---|---|---|
| queued（排队中） | 灰 `#8c8c8c` | ClockCircle |
| running（运行中） | 蓝 `#1677ff` + 旋转 | Loading |
| finished（已完成） | 绿 `#52c41a` | CheckCircle |
| failed（失败） | 红 `#ff4d4f` | CloseCircle |

- 主题色 `#1677ff`（AntD 默认），深色导航 `#001529`
- 本期只做浅色主题；深色主题列入后续
- 所有数字表格：右对齐 + 千分位；百分比保留 2 位；指标卡用 `statistic` 组件统一风格

### 4.4 组件规范

| 组件 | 规范 |
|---|---|
| 表格 | 服务端分页样式（mock 分页）、列排序/筛选、行高紧凑（size=middle）、状态列用 Tag、操作列右对齐 |
| 表单 | 左标签右控件、必填项红星、校验失败即时提示、提交按钮 loading 态 |
| 图表 | ECharts；统一 tooltip 样式、图例可点选隐藏；空数据时显示空态占位而非空白 |
| 反馈 | 操作成功 message 提示；危险操作（重试/取消/删除）二次确认 Modal；全局异常 errorResult 页 |

### 4.5 全局状态规范（每页必须覆盖）

| 状态 | 规范 |
|---|---|
| 加载中 | Skeleton 骨架屏（表格用 Table loading，图表用 Spin） |
| 空态 | Empty 组件 + 引导文案 + 行动按钮（如"去提交任务"） |
| 错误态 | errorResult + 重试按钮 |
| 无权限 | 403 占位页（登录页/顶栏演示，可 mock 切换角色触发） |

### P2 总览 Dashboard

**目的**：登录后 3 秒了解全局——数据规模、任务动态、回测表现。

**线框**：

```
┌──────────────────────────────────────────────────┐
│ 统计卡行（4 卡）：                                   │
│ [股票数 5,432] [数据区间 2021-06-18 ~ 2026-06-16]    │
│ [股票池 1 个]  [因子运行 0 个]                        │
├──────────────────────────────────────────────────┤
│ 最近任务（表格，6 行 + 查看全部→任务中心）               │

├──────────────────────────────────────────────────┤

├──────────────────────────────────────────────────┤

└──────────────────────────────────────────────────┘

**元素**：统计卡（`statistic` 组件，主数字 + 副标题）、最近任务表、Top 回测表、净值曲线（tooltip 显示当日净值和回撤）。

### P3 任务中心（体验核心页）

**目的**：监控后台任务全生命周期，失败可重试。原型重点验证：状态切换动效、进度条、日志流。

**线框**：

```
│ 筛选区：[状态:全部▾] [类型:全部▾] [搜索框___] [刷新按钮]
│ ┌───────────────────────────────────────────────┐
│ │ 任务ID  | 类型  | 名称     | 状态   | 进度条 | 提交时间  | 耗时 | 操作    │
│ │ #1031   | 回测  | momentum20| 运行中 | ▓▓▓░ 62% | 10-07 09:12 | 3m22s | 查看    │
│ │ #1030   | 回测  | turnover | 已完成 | ▓▓▓▓ 100%| 10-07 08:47 | 4m01s | 查看结果 │
│ │ #1029   | 因子生成| run_101 | 失败   | ▓░ 18%   | 10-07 08:12 | 1m15s | 重试/查看│
│ │ #1028   | 建池  | liquid500| 排队中 | ░ 0%     | 10-07 08:10 | -    | 取消    │
│ └───────────────────────────────────────────────┘
│ 模拟控制（原型专用）：[▶ 推进 #1028 运行] [▶ 完成 #1031] [▶ 使 #1031 失败]
```

**元素**：筛选工具栏、任务表格（分页 10 条/页）、任务详情抽屉、原型专用"状态推演控制器"。

**任务详情抽屉**（点"查看"展开，宽 480px）：

```
│ 任务 #1031 详情                    [关闭]
│ 类型/名称/提交人/提交时间/参数摘要(JSON折叠)
│ ┌─ 日志（实时滚动，尾部追加，失败行标红）─────┐
│ │ [09:12:01] 读取股票池 liquid_500 ... │
│ │ [09:13:40] 回测进度 45%              │
│ │ [09:15:03] ▓ 完成，结果已保存          │
│ └──────────────────────────────────┘
│ [查看结果]（finished 时可用）  [重试]（failed 时可用）
```

**交互**：进度条每 2 秒自动更新（mock 定时器，无需用户操作）；状态变化时行内 Tag 变色 + 轻微动效；日志自动滚到底部；失败任务"重试"二次确认后状态回到 queued；取消仅对 queued 可用。

**Mock 要求**：预置 12 条任务覆盖 6 种类型 × 4 种状态；日志内容按任务类型拟真（建池日志、回测进度日志、PPO 训练日志各自不同）；"状态推演控制器"仅原型可见，正式版移除。

│ └─────────────────────────┘    │                              │
```

**元素**：表达式输入（等宽字体、示例可点击填入）、股票池下拉（"全部数据/liquid_500"）、日期区间（默认取数据全区间）、6 个数值参数（带单位提示、越界校验）、提交按钮、右侧空态/结果态。

**交互**：必填与数值校验即时提示；提交成功后：按钮 loading → 顶部 message 成功 → 自动跳转任务中心（携带新任务 ID 高亮）→ 任务完成后从任务卡片进结果详情；右侧结果区同时展示一条"最近一次完成的示例结果"（复用 P5 数据），避免原型演示时右侧永远是空态。

**Mock 要求**：提交后 5 秒内新任务出现在任务中心并自动推进至完成（配合 P3 推演控制器可改为手动推进）。

## 6. Mock 数据字典（必须与真实系统口径一致）

原型数据必须来自真实系统的口径，避免演示时被业务方当场识破：

| 类别 | 值 |
|---|---|
| 股票规模 | 5,432 只；数据区间 2021-06-18 ~ 2026-06-16；约 600 万行 |
| 股票池 | `liquid_500`（500 只）；`pool_id` 形如 `liquid_500_864dc25f` |
| 任务类型 | `prepare_master`（主缓存导入）、`create_pool`（建池）、`generate_factors`（因子生成）、`backtest_factors`（因子批量回测）、`compose_factors`（因子组合）、`manual_backtest`（手动回测） |
| 任务状态 | `queued / running / finished / failed` |
| 回测指标 | 年化收益、夏普、最大回撤、换手率、交易成本、胜率；净值、日收益、回撤序列 |
| 因子指标 | IC、RankIC、ICIR、coverage、score（因子生成场景，原型日志中提及） |
| 表达式示例 | `close / delay(close, 20) - 1`、`-rank(TurnoverRate)`、`close / ts_mean(close, 20) - 1` |
| 回测参数默认 | TopK=50、买入费率 0.0015、卖出 0.0015、滑点 0.0005、最低手续费 5、单票权重上限 0.02、初始资金 1 亿 |

Mock 数据之间的**联动约束**：P2 最近任务 = P3 任务表前 6 条；P4 提交的新任务必须出现在 P3；P5 展示的任务 #1030 必须在 P3 中状态为 finished 且参数一致。

## 7. 原型验收标准

- [ ] 5 个页面全部可点击到达，无死链；菜单置灰项有"规划中"提示
- [ ] 全站 4 种任务状态色、加载/空/错误三态在任何页面均可见可触发

- [ ] P4 表单校验完整（必填、数值范围），提交闭环到 P3 新任务出现
- [ ] P3 → P5 数据联动一致（同一任务 ID 的参数、指标、日志对应）
- [ ] 所有表格支持排序/筛选（mock 实现），分页正常
- [ ] 1366×768 分辨率下无横向滚动、无组件溢出
- [ ] 图表均可缩放、悬停 tooltip 信息完整
- [ ] 研究员/管理员两种角色登录后顶栏角色标识不同（权限差异本期仅演示，不做真实拦截）

## 9. 风险与备注

1. **原型与正式的边界**：mock 层目录结构必须与未来 API 路由一一对应（如 `GET /api/tasks`、`POST /api/backtests`），替换时只换 adapter 不换页面代码
2. **图表保真**：净值曲线的 mock 序列建议用真实回测输出的形态（截取一段真实 daily_report.csv 的净值序列脱敏使用），避免原型图与真实效果落差
3. **任务推演控制器**为原型专用，正式版必须移除，防止误操作
4. 深色主题、移动端、SSO 明确为后续迭代，不在本期验收范围
